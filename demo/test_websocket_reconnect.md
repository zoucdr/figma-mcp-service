# WebSocket 断线重连测试指南

## 快速测试步骤

### 准备工作

1. 启动 figma-deliver 服务
   ```bash
   cd service
   go run main.go
   # 或
   ./figma-service.exe
   ```

2. 在 Figma 中加载插件
   - 打开 Figma Desktop
   - Plugins → Development → Import plugin from manifest
   - 选择 `figma-plugin/manifest.json`

### 测试 1: 基础连接和心跳

**步骤**：
1. 打开插件，输入服务器地址 `localhost:8080`
2. 点击 "Connect"
3. 观察连接状态变为 "Connected to localhost:8080"
4. 打开浏览器控制台（插件 UI 上右键 → Inspect）
5. 等待 30 秒，观察控制台输出

**预期结果**：
- 连接成功，状态显示绿色
- 控制台每 30 秒输出一次：`💓 发送心跳 ping`
- （如果服务器支持）收到：`💓 收到心跳 pong`

---

### 测试 2: 网络断开重连（短时间）

**步骤**：
1. 保持插件连接状态
2. 关闭服务器（Ctrl+C）或断开网络
3. 观察插件状态变化
4. 等待 3 秒
5. 重启服务器或恢复网络
6. 观察重连过程

**预期结果**：
```
1. 状态变为：🔄 重连中 (第 1 次尝试，1秒后重试)
2. 1秒后：🔄 正在重连... (第 1 次)
3. 失败后：🔄 重连中 (第 2 次尝试，2秒后重试)
4. 服务器恢复后：✅ Connected to localhost:8080
5. 重连次数重置为 0
```

**控制台日志**：
```
🔌 WebSocket 连接已关闭 (code: 1006, reason: )
检测到连接丢失，准备重连...
⏰ 计划 1 秒后进行第 1 次重连...
🔄 尝试重连... (第 1 次)
✅ WebSocket 连接已打开
```

---

### 测试 3: 指数退避策略

**步骤**：
1. 保持插件连接状态
2. 关闭服务器（不要重启）
3. 观察前 5 次重连的间隔时间
4. 记录每次重连的等待时间

**预期结果**：
```
第 1 次: 1 秒后重试   ✅
第 2 次: 2 秒后重试   ✅
第 3 次: 4 秒后重试   ✅
第 4 次: 8 秒后重试   ✅
第 5 次: 16 秒后重试  ✅
第 6 次: 30 秒后重试  ✅
第 7 次: 30 秒后重试  ✅（达到最大延迟）
```

**控制台日志示例**：
```
⏰ 计划 1 秒后进行第 1 次重连...
🔄 尝试重连... (第 1 次)
重连失败 (第 1 次): ...
⏰ 计划 2 秒后进行第 2 次重连...
🔄 尝试重连... (第 2 次)
...
```

---

### 测试 4: 网络恢复快速重连

**步骤**：
1. 保持插件连接状态
2. 禁用电脑网络（WiFi 或网线）
3. 观察状态变为"网络离线"
4. 等待插件进入第 3 或 4 次重连（8-16秒间隔）
5. **在下次重连前**启用网络
6. 观察是否立即重连（不等待剩余时间）

**预期结果**：
- 网络离线时显示：`🌐 网络离线，等待网络恢复...`
- 网络恢复时立即显示：`🌐 网络已恢复，正在重连...`
- 不等待原定的重连时间，立即尝试连接
- 连接成功

**控制台日志**：
```
🌐 网络已离线
⏰ 计划 8 秒后进行第 4 次重连...
[用户恢复网络]
🌐 网络已恢复在线
网络恢复，立即尝试重连...
🔄 尝试重连... (第 4 次)
✅ WebSocket 连接已打开
```

---

### 测试 5: 手动断开（不自动重连）

**步骤**：
1. 保持插件连接状态
2. 点击 "Disconnect" 按钮
3. 观察状态变化
4. 等待 30 秒以上
5. 确认没有自动重连

**预期结果**：
- 状态变为：`已手动断开连接`（红色）
- 控制台输出：`🔌 手动断开连接`
- 不显示"取消自动重连"按钮
- 不进行任何重连尝试
- "Connect" 按钮恢复可用状态

---

### 测试 6: 取消自动重连

**步骤**：
1. 保持插件连接状态
2. 关闭服务器，触发自动重连
3. 等待状态显示"重连中"
4. 点击 "取消自动重连" 按钮
5. 观察状态变化

**预期结果**：
- 重连中时显示蓝色"取消自动重连"按钮
- 点击后按钮消失
- 状态变为：`已取消自动重连`（红色）
- 停止所有重连尝试
- "Connect" 按钮恢复可用状态

**控制台日志**：
```
🚫 用户取消自动重连
```

---

### 测试 7: 长时间断线恢复

**步骤**：
1. 保持插件连接状态
2. 关闭服务器
3. 让插件持续重连至少 5 分钟（10 次以上重连）
4. 启动服务器
5. 观察下次重连时是否成功

**预期结果**：
- 长时间重连保持 30 秒间隔（不继续增加）
- 重连次数持续增加（第 10, 11, 12... 次）
- 服务器恢复后，下次重连成功
- 连接成功后重连次数重置为 0

---

### 测试 8: 页面切换恢复

**步骤**：
1. 保持插件连接状态
2. 最小化 Figma 或切换到其他应用
3. 在后台等待 2 分钟
4. 关闭服务器（插件在后台时）
5. 切回 Figma
6. 观察是否检测到断线并重连

**预期结果**：
- 切回前台时检测到连接断开
- 控制台输出：`👁️ 页面变为可见`
- 如果未连接，立即尝试重连

---

### 测试 9: 心跳超时触发重连

**步骤**：
1. 保持插件连接状态
2. 在服务器端模拟：接受连接但不响应消息（不关闭连接）
3. 等待 30 秒（心跳间隔）
4. 观察心跳发送
5. 如果心跳发送失败，观察是否触发重连

**预期结果**：
- 30 秒后发送心跳：`💓 发送心跳 ping`
- 发送失败时输出：`心跳发送失败: ...`
- 触发重连流程

**注意**：此测试需要服务器配合（暂停响应但不关闭连接）

---

### 测试 10: 服务器拒绝连接

**步骤**：
1. 确保服务器未启动
2. 在插件中点击 "Connect"
3. 观察重连过程
4. 在第 3 次重连时启动服务器
5. 观察连接恢复

**预期结果**：
- 首次连接失败后开始重连
- 状态显示：`🔄 重连中 (第 X 次尝试，Y秒后重试)`
- 服务器启动后的下次重连成功

---

## 异常情况测试

### 异常 1: 快速反复断开/连接

**步骤**：
1. 连接成功后
2. 快速重复：关闭服务器 → 启动服务器 → 关闭服务器（每次间隔 2-3 秒）
3. 观察插件是否能正确处理

**预期**：不会出现重复连接或状态混乱

### 异常 2: 修改连接参数后断线

**步骤**：
1. 连接到 `localhost:8080`
2. 断开连接（手动）
3. 修改端口为 `9999`
4. 关闭服务器
5. 点击 "Connect"（会失败并重连）
6. 启动服务器在 8080 端口（而不是 9999）
7. 观察是否继续尝试连接 9999

**预期**：插件继续尝试连接 9999（新设置），不会回退到 8080

## 调试技巧

### 打开控制台

1. 在插件 UI 上右键点击
2. 选择 "Inspect"
3. 切换到 "Console" 标签

### 关键日志

搜索以下关键词：
- `💓` - 心跳相关
- `🔄` - 重连相关
- `🔌` - 连接状态
- `🌐` - 网络状态
- `✅` - 成功操作
- `❌` - 错误信息

### 监控网络

1. 在控制台切换到 "Network" 标签
2. 筛选 "WS"（WebSocket）
3. 观察连接建立和关闭

## 常见问题

### Q1: 重连次数一直增加，无法连接

**可能原因**：
- 服务器未启动
- 端口号错误
- 防火墙阻止连接

**解决方法**：
1. 确认服务器正在运行
2. 检查端口配置是否正确
3. 点击"取消自动重连"，修正配置后重新连接

### Q2: 显示"网络离线"但网络正常

**可能原因**：
- 浏览器误报（Figma 插件环境问题）
- 本地防火墙阻止

**解决方法**：
1. 手动刷新插件
2. 重启 Figma

### Q3: 心跳发送但没有 pong 响应

**可能原因**：
- 服务器未实现 pong 响应
- 心跳消息格式不匹配

**解决方法**：
- 不影响功能，只是日志不显示 pong
- 服务器可选实现 pong 响应

### Q4: 重连成功但功能异常

**可能原因**：
- 服务器状态未恢复
- Channel 信息丢失

**解决方法**：
1. 手动断开重连
2. 检查服务器日志

## 性能验证

### 内存占用

**测试**：长时间运行（1小时），频繁断线重连（每分钟一次）

**预期**：内存占用稳定，无明显泄漏

### CPU 占用

**测试**：重连过程中观察 CPU 占用

**预期**：重连时短暂增加（< 1%），稳定后恢复正常

### 网络流量

**测试**：统计心跳消息流量

**预期**：
- 心跳消息大小：< 50 bytes
- 每小时流量：< 10 KB
- 对用户网络无明显影响

## 总结

完成以上测试后，WebSocket 断线重连机制应该能够：

✅ 在各种网络环境下稳定运行  
✅ 快速恢复短暂的网络抖动  
✅ 长期保持连接或持续重连  
✅ 提供清晰的状态反馈  
✅ 支持用户手动控制  

如发现问题，请参考控制台日志进行调试。
