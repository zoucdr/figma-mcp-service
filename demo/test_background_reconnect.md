# WebSocket 后台重连测试指南

本文档提供测试 Figma 插件后台重连功能的详细步骤。

## 前置准备

1. 启动 WebSocket 服务器（默认端口 8080）
2. 在 Figma 中安装并打开插件
3. 打开浏览器控制台（查看日志）

## 测试场景

### 场景 1: 短时间后台切换

**目的**: 验证短时间后台后能立即恢复连接

**步骤**:
1. 在插件中连接到 WebSocket 服务器
2. 确认连接成功（状态显示"已连接"）
3. 切换到其他应用（例如浏览器、VSCode）
4. 等待 10 秒
5. 切回 Figma

**预期结果**:
```
👁️ 页面变为可见
连接状态检查: state.connected=true, socket.readyState=1
连接正常，重启心跳...
💓 发送心跳 ping
🔍 健康检查: 连接正常
```
- ✅ 连接自动恢复
- ✅ 无需手动重新连接
- ✅ 状态保持"已连接"

---

**步骤**:
1. 在插件中连接到 WebSocket 服务器
2. 确认连接成功
3. 切换到其他应用
4. 等待 5 分钟（让 WebSocket 连接超时断开）
5. 切回 Figma

```
连接状态检查: state.connected=true, socket.readyState=3
检测到连接已断开，立即重连...
🔄 尝试重连... (第 1 次)
Connecting to: ws://localhost:8080/mcp-ws
✅ WebSocket 连接已打开
Joining channel: figma-bridge
Connected to localhost:8080 in channel: figma-bridge
```
- ✅ 自动检测到连接断开
- ✅ 立即触发重连
- ✅ 重连成功后恢复正常

### 场景 4: 健康检查机制

**目的**: 验证定期健康检查能发现连接断开

**步骤**:
1. 在插件中连接到 WebSocket 服务器
2. 打开浏览器控制台
3. 在服务器端强制断开连接（或关闭服务器）
4. 等待最多 10 秒

**预期结果**:
```

检测到连接丢失，准备重连...

```
或者:
```
🔍 健康检查: 发现连接已断开，但状态未更新
检测到连接丢失，准备重连...
```
- ✅ 在 10 秒内检测到连接断开
- ✅ 自动触发重连机制
- ✅ 开始指数退避重连

## 调试技巧

### 查看当前连接状态

在浏览器控制台输入:
```javascript
console.log('Connected:', state.connected);
console.log('Socket state:', state.socket ? state.socket.readyState : 'null');
console.log('Manual disconnect:', state.manualDisconnect);
console.log('Reconnecting:', state.reconnecting);
console.log('Reconnect attempts:', state.reconnectAttempts);
```

### WebSocket readyState 值说明

- `0` - CONNECTING (连接中)
- `1` - OPEN (已打开)
- `2` - CLOSING (关闭中)
- `3` - CLOSED (已关闭)

### 强制触发重连

在浏览器控制台输入:
```javascript
if (state.socket) state.socket.close();
```

### 模拟后台挂起

在浏览器控制台输入:
```javascript
// 停止心跳
clearInterval(state.heartbeatTimer);
// 等待 15 秒后重启
setTimeout(() => startHeartbeat(), 15000);
```

## 常见问题

### Q1: 为什么切回 Figma 后连接没有立即恢复？

**A**: 检查以下几点:
1. 是否点击了"断开连接"（手动断开不会自动重连）
2. 查看控制台是否有报错
3. 确认服务器是否运行正常
4. 尝试手动点击"连接"

### Q2: 重连次数过多怎么办？

**A**: 这通常说明服务器不稳定或网络有问题:
1. 点击"取消自动重连"停止重连
2. 检查服务器日志
3. 检查网络连接
4. 修复问题后手动重新连接

### Q3: 心跳日志太多怎么办？

**A**: 可以在代码中注释掉心跳日志:
```javascript
// console.log("💓 发送心跳 ping");
```

### Q4: 如何调整重连间隔？

**A**: 修改 `state` 中的配置:
```javascript
state: {
  minReconnectDelay: 2000,  // 改为 2 秒
  maxReconnectDelay: 10000, // 改为 10 秒
}
```
