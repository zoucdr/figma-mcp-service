## 🚀 快速开始

### 步骤 1: 重启服务

由于修改了数据库模型，需要重启服务让GORM自动迁移数据库：

```bash
# 停止现有服务（如果正在运行）
# 然后启动服务
cd d:\figma-deliver\service
go run main.go

# 或者如果已编译
.\figma-deliver.exe
```

### 步骤 2: 配置代理

1. **登录系统**
   - 打开浏览器访问 http://localhost:8080
   - 使用您的账号登录

2. **进入个人资料**
   - 点击顶部的用户名下拉菜单
   - 选择"个人资料"

3. **配置代理**
   - 找到"代理配置"卡片
   - 打开"启用代理"开关
   - 输入代理地址，例如:
     - `http://127.0.0.1:7890` (Clash)
     - `socks5://127.0.0.1:1080` (Shadowsocks)
   
4. **测试代理**
   - 点击"测试代理连接"按钮
   - 等待测试结果
   - 如果成功，会显示"代理连接测试成功"

5. **保存配置**
   - 点击页面底部的"保存所有设置"按钮

### 步骤 3: 验证代理工作

配置完成后，所有Figma API请求将自动使用代理。在控制台可以看到：

```
✅ 用户 your_username 使用代理: http://127.0.0.1:7890
```

## 📋 支持的代理类型

### HTTP代理
```
http://127.0.0.1:7890
http://proxy.example.com:8080
```

### HTTPS代理
```
https://proxy.example.com:8443
```

### SOCKS5代理
```
socks5://127.0.0.1:1080
```

### 带认证的代理
```
http://username:password@proxy.example.com:8080
socks5://user:pass@127.0.0.1:1080
```

## 🔧 常见代理工具配置

### Clash
- 默认HTTP代理端口: `7890`
- 默认SOCKS5端口: `7891`
- 配置: `http://127.0.0.1:7890`

### V2Ray / V2RayN
- 默认SOCKS5端口: `10808`
- 默认HTTP端口: `10809`
- 配置: `socks5://127.0.0.1:10808`

### Shadowsocks
- 默认端口: `1080`
- 配置: `socks5://127.0.0.1:1080`

### Proxifier / Proxycap
- 根据您的配置设置
- 通常是HTTP或SOCKS5代理

## 🐛 故障排除

### 代理测试失败
1. **检查代理工具是否运行**
   ```bash
   # Windows检查端口
   netstat -an | findstr "7890"
   ```

2. **检查代理地址格式**
   - 必须包含协议前缀（http://, socks5://）
   - 端口号正确
   - 没有多余的空格

3. **检查代理工具设置**
   - 允许本地连接
   - 防火墙没有阻止

### 代理配置后请求仍失败
1. **检查控制台输出**
   - 看是否显示"使用代理"消息
   - 如果显示"代理配置错误，使用直连"，说明代理URL格式错误

2. **测试代理可用性**
   - 在浏览器中配置相同的代理
   - 访问 https://api.figma.com 测试

3. **检查代理速度**
   - 代理服务器可能很慢
   - 尝试更换其他代理节点

## 💡 使用建议

### 何时使用代理

1. **遇到429错误时**
   - Figma API限流
   - 短时间内请求过多
   - IP被限制

2. **网络访问受限时**
   - 无法直接访问Figma API
   - 需要通过代理访问外网

3. **提高访问速度时**
   - 使用CDN加速代理
   - 选择地理位置更近的代理节点

### 代理选择建议

1. **稳定性优先**
   - 选择稳定的代理服务
   - 避免频繁断连

2. **速度考虑**
   - 选择延迟低的节点
   - 带宽充足的代理

3. **安全性**
   - 使用可信的代理服务
   - 避免使用公共免费代理

## 📝 技术细节

### 代理工作流程

```
1. 用户配置代理 → 保存到数据库
2. 发起Figma API请求
3. 根据token查找用户
4. 检查用户是否启用代理
5. 如果启用，创建带代理的HTTP客户端
6. 发送请求（通过代理）
7. 接收响应
```

### 影响的API调用

所有使用 `CreateHTTPClientWithToken(token)` 的请求都会使用代理：
- `GetFigmaNodes()` - 获取节点信息
- `DownloadPreviewFigmaImageWithOptions()` - 下载预览图
- `DownloadFilteredPreviewFigmaImage()` - 下载过滤预览图
- `DownloadFilteredPreviewFigmaImages()` - 批量下载

### 日志输出

成功使用代理：
```

```

代理配置错误：
```
⚠️ 用户 username 代理配置错误，使用直连: 无效的代理URL
```

## ⚠️ 注意事项

1. **代理配置是用户级的**
   - 每个用户可以配置自己的代理
   - 不影响其他用户

2. **代理失败会回退**
   - 如果代理连接失败
   - 自动使用直连
   - 不会中断服务

3. **数据安全**
   - 代理URL存储在数据库
   - 只有用户自己可见
   - 不会泄露给其他用户

4. **性能影响**
   - 代理会增加请求延迟
   - 取决于代理服务器速度
   - 关闭代理后恢复正常
